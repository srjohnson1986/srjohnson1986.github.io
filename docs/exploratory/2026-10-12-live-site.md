# Session: live site, visitor and recruiter trip hazards

- Date: 2026-10-12
- Target: https://srjohnson1986.github.io/ as deployed from `main` at 8523ac3 (all 14 public pages, including the four resume versions)
- Tester: Claude Code, driving the Claude desktop app's built-in browser pane. It offers the same kind of tools as the Playwright MCP server (page reads from the accessibility tree, clicks, key presses, window resize, console and network access). The Playwright MCP server was configured in #284 during this session, but Claude Code loads a new project-scoped server only after a restart and a one-time approval, so it was not the tool used. The next session should use it.
- Time box: one sitting. No stopwatch was kept.

## Charter

Explore the live site as a visitor or recruiter would, looking for anything they would trip over: navigation, the Development & QA, Audio, and Art filters, resume version switching, PDF links, theme switching, phone-width layout, and keyboard-only use.

## Covered

- **Development & QA filters:** single and combined tags (a project must have every tag), clear, deep links, an unknown tag, the "Filters · N selected" note on a closed panel, keyboard use (Enter on the summary, Tab, Space), and that a change adds no history entry.
- **Audio filters:** every year, band, and role option checked against the cards shown, and against the count in the status line and the role counts; combinations; deep links; the empty state; unknown values in the link.
- **Art filters:** sort (newest and oldest), every year, format, and tag option checked the same way; deep links; unknown values in the link; the larger-image view opened and closed from the keyboard (focus moves in, Escape closes, focus returns to the image).
- **Resume:** all four versions load with the right title, the current version marked in the switcher, and each version's PDF link returns 200, `application/pdf`, a `%PDF-` header, and a plausible size. `/resume/` forwards at once and Back is not trapped.
- **Theme:** the button switches, relabels, remembers the choice, and the page colors change.
- **Phone width (320px and 375px):** no horizontal overflow on 9 pages; the phone menu opens and lists every page; tap targets measured on the Creative page.
- **Keyboard only (desktop):** tab order through the skip link, header, and the open Development & QA list; the filter panel; the larger-image view.
- **Links:** every external link on every page (target, `rel`, and whether it is alive), unknown addresses (real 404 with the friendly page), and the Audio players (lazy, one visible light or dark pair per release, unique titles).

## Found

| # | Finding | Severity | Issue | Test | Fix |
| --- | --- | --- | --- | --- | --- |
| 1 | A link with a value a dropdown does not offer (`/audio/?year=1999`, `/art/?sort=foo&format=bogus`) shows everything but leaves the dropdown blank | Medium | #285 | filters.spec.ts, art-filters.spec.ts | #288 |
| 2 | Escape does not close the phone menu, though it closes the lists on a wide screen | Low | #286 | navigation.spec.ts | #289 |

Both tests failed on the bug before the fix. Two behaviors that were already fine were also locked in with tests (#287, #290): the Back button is not trapped by the `/resume/` redirect, and changing a filter adds no history entry. Each was proved by a deliberate break.

Reviewed and left alone:

- The Filters panel starts closed, but its title says how many filters are on, so a deep link is not silently filtered.
- Tag counts do not narrow as other filters are applied, so a combination such as 2020 and Fat Sally can give no results. The empty message says what to do. This is a design choice, not a defect.
- `$60 /hour` has a space before the unit in `src/data/studio.yaml`. It reads as a styling choice, not an error.
- `/Audio/` (capital A) is a 404. GitHub Pages paths are case-sensitive and the 404 page is friendly.
- The `Art` link measured 21px wide on the Creative page at 320px. It is an inline link in running text, which WCAG 2.2 exempts from the 24px target size rule.
- LinkedIn returns HTTP 999 to scripts. That is its bot block, not a dead link.
- One of my own probes reported role and year mismatches on Audio and Art. That was my script (a regular expression that included the count in the label, and nested list items counted as cards), not the site. Noted so the same probe is not trusted again.

## Not covered

- Real devices and other engines: iOS Safari, Android Chrome on hardware, Firefox, Safari. Only a Chromium window resized to phone widths was used, with desktop pointer events.
- Anything inside the Bandcamp players (they are cross-origin iframes): playing, the keyboard behavior inside them, and how many tab stops 40 players add on the Audio page.
- Screen readers. Structure and names were read from the accessibility tree, but nothing was listened to.
- The PDFs' visual quality. Link, type, and size were checked, not how the pages look.
- Slow networks, scripts off, and a very short window (landscape phone).
- Depth on Home, Contact, Jabroni Fest, and the project pages: loaded, measured for overflow, and checked for external links, but not read for wording.
- The Art stories and series (expand, collapse) beyond the larger-image view.
- Dark mode at phone width, page by page (axe scans cover it in CI).

## Kept manual

These stay as exploratory checks on purpose, because automating them would cost more than it returns or would not test the thing that matters:

- **How a page looks at phone width.** Tests check there is no overflow and the header is on one line; whether the layout looks right (for example the theme button wrapping onto its own row at 320px) is a judgment a screenshot comparison would only turn into noise.
- **Third-party players.** Bandcamp is stubbed in the suite so tests never use the network. Whether the real players load and play, and how they behave from the keyboard, can only be checked against the real thing, and it is not ours to fix.
- **Screen reader experience.** axe checks names, roles, and landmarks. Whether the page is pleasant to listen to needs a person and a screen reader.
- **Real devices and other browsers.** The CI suite runs Chromium only. A short pass on a real phone and in Firefox and Safari is worth doing before a job search starts.
- **Tab-stop volume on the Audio page.** Forty embedded players mean many tab stops. The intro links straight to the rates, and the filters narrow the list, but whether that is enough is a judgment call.
- **Tone of the wording.** Tests check that the text matches the data files, not that it reads well.
